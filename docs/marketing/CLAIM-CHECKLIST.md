# AutoCite Pre-Publication Claim Checklist

Run this checklist before publishing a page, release note, launch post, directory listing, screenshot, or demo.

## Release state

- [ ] Every described interface exists in the latest public release.
- [ ] Development previews are labeled as previews.
- [ ] Download filenames and operating systems match the release page.
- [ ] Checksums, signatures, installers, or attestations are mentioned only when attached to that release.

## Privacy

- [ ] “Local-first” is used instead of “never connects to the internet.”
- [ ] Optional CourtListener retrieval is disclosed when relevant.
- [ ] Model downloads and hosted deployments are not described as offline.
- [ ] No confidential or third-party unpublished text appears in screenshots or demos.
- [ ] Scanner share payloads contain counts and categories only.

## Accuracy

- [ ] No complete or guaranteed Bluebook compliance claim.
- [ ] No universal accuracy percentage without a directly linked evaluation and scope.
- [ ] No good-law, citator, proposition-support, controlling-authority, or precedential-weight conclusion.
- [ ] “Mechanically clean” is limited to supported deterministic checks.
- [ ] Source matching is not described as substantive legal support.

## Affiliations and proof

- [ ] No fake testimonials, ratings, user counts, customer logos, or adoption metrics.
- [ ] No court, school, journal, law-firm, Bluebook, CourtListener, or Free Law Project endorsement is implied.
- [ ] Open-source, license, evaluation, and packaging claims point to public evidence.
- [ ] Comparisons describe architecture or documented behavior rather than unsupported superiority.

## Accessibility and distribution

- [ ] Images have useful alt text.
- [ ] Videos are captioned.
- [ ] Essential claims are available as text, not image-only copy.
- [ ] Community rules permit the post.
- [ ] No fake votes, reviews, backlinks, stars, or automated engagement are used.
